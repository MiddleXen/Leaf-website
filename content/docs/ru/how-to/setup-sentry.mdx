---
title: Настройка Sentry
---

[Sentry](https://sentry.io/) — это сервис отслеживания ошибок и мониторинга производительности приложений в реальном времени. Интеграция с Sentry позволяет серверу Leaf автоматически собирать исключения и стек-трейсы, что существенно упрощает диагностику и устранение сбоев.

В этом руководстве описано, как настроить отправку отчётов об ошибках из Leaf в ваш проект Sentry.

## Подготовка

1. **Учётная запись Sentry:** Зарегистрируйтесь на [sentry.io](https://sentry.io/). Бесплатного тарифа достаточно для большинства серверов.
2. **Проект в Sentry:** Создайте новый проект внутри вашей организации Sentry.
   - При выборе платформы укажите **Java** (или "Other"). Выбор платформы влияет лишь на базовые подсказки от Sentry, интеграция внутри Leaf уже встроена.
3. **DSN (Data Source Name):** После создания проекта перейдите в его настройки (Settings) -> "Client Keys (DSN)". Скопируйте строку DSN — она выглядит как URL (например, `https://xxxxxxxxxxxxxxxxxxxxxxxx@o######.ingest.sentry.io/#######`).

## Пошаговая настройка

1. **Откройте конфигурацию Leaf:** Откройте основной файл настроек `leaf-global.yml` в папке `config/` (или в корне сервера).

2. **Найдите секцию Sentry:** Внутри файла найдите блок `sentry:`. По умолчанию он выглядит следующим образом:

    ```yaml
    sentry:
      # Sentry DSN для логирования ошибок. Оставьте пустым для отключения.
      # Получить ключ можно на https://sentry.io/
      dsn: ""
      # Минимальный уровень логируемых сообщений.
      log-level: WARN
      # Записывать только сообщения, содержащие Throwable (исключения со стек-трейсом).
      only-log-thrown: true
    ```

3. **Задайте параметры:**
   - **`dsn`:**
     - Вставьте скопированный DSN внутрь кавычек.
     - **Пример:** `dsn: 'https://xxxxxxxxxxxxxxxxxxxxxxxx@o######.ingest.sentry.io/#######'`
     - _Если поле пустое, интеграция с Sentry отключена._

   - **`log-level`:**
     - Определяет минимальный уровень важности сообщений для отправки в Sentry (`ERROR`, `WARN`, `INFO`, `DEBUG`).
     - Значение по умолчанию `WARN` означает, что будут отправляться предупреждения и ошибки (включая исключения).
     - Если вы хотите получать только критические ошибки, укажите `ERROR`.
     - **Рекомендация:** оставьте `WARN`.

   - **`only-log-thrown`:**
     - При значении `true` (по умолчанию) в Sentry отправляются _только_ те логи, которые содержат Java `Throwable` (исключения с полным стек-трейсом). Это исключает лишний информационный шум.
     - При `false` будет отправляться любое сообщение, подходящее под порог `log-level`.
     - **Рекомендация:** оставьте `true`.

4. **Сохраните файл и перезапустите сервер:**
   - Сохраните изменения в `leaf-global.yml`.
   - Полностью перезапустите сервер Leaf, чтобы параметры вступили в силу.

## Возможные неполадки

- **Ошибки не появляются в панели Sentry:**
  - Проверьте правильность строки `dsn` (она должна быть заключена в одинарные кавычки в YAML).
  - Убедитесь, что `log-level` не завышен (например, при уровне `ERROR` предупреждения не отправляются).
  - Проверьте, не блокирует ли фаервол исходящие соединения на `ingest.sentry.io` по порту 443 (HTTPS).
- **Слишком много уведомлений:**
  - Повысьте `log-level` до `ERROR`.
  - Убедитесь, что параметр `only-log-thrown` установлен в `true`.
