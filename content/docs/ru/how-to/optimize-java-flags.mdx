## Перед началом работы: базовые правила

Качественная оптимизация требует методичного подхода. Подробные шаги описаны в руководстве [«Оптимизация сервера Leaf»](./optimize-leaf-server). Вкратце:

1. **Создайте резервную копию:** Перед внесением любых изменений сделайте бэкап сервера.
2. **Профилируйте, а не угадывайте:** Используйте [Spark](https://spark.lucko.me/) для выявления реальных узких мест (паузы GC, скачки MSPT, высокое потребление памяти).
3. **Меняйте параметры постепенно:** Не изменяйте всё сразу — корректируйте по одному флагу или блоку параметров, перезапускайте сервер и сравнивайте показатели.

## Выбор среды выполнения Java (JRE / JDK)

- **Рекомендация:** Используйте свежий LTS-релиз Java 21 от проверенных поставщиков OpenJDK с поддержкой современных сборщиков мусора (G1GC, Generational ZGC, Shenandoah):
  - **Adoptium Eclipse Temurin:** Популярный дистрибутив OpenJDK с открытым исходным кодом и поддержкой сообщества.
  - **Amazon Corretto:** Надёжный промышленный дистрибутив OpenJDK с длительной поддержкой от Amazon.
  - **GraalVM (на базе OpenJDK):** Обеспечивает повышенную производительность благодаря продвинутому JIT-компилятору Graal.
- **Избегайте:** Сборок с суффиксом `-headless`, так как в них могут отсутствовать компоненты, требуемые серверным окружением Minecraft.

## Флаги запуска Java (аргументы JVM) — Сборка мусора (GC)

Флаги Java определяют режим работы виртуальной машины, управление памятью и поведение сборщика мусора (Garbage Collection — GC).

### Базовый стандарт: Флаги Aikar'а (G1GC)

- **Назначение:** Флаги Aikar'а — это проверенный временем набор аргументов для сборщика G1GC (Garbage-First Garbage Collector). G1GC является сборщиком по умолчанию в современных версиях Java и обеспечивает отличный баланс между пропускной способностью (throughput) и длительностью пауз (pause time).
- **Применение:** Идеальный выбор для большинства серверов (примерно от 1 до 100 игроков). Набор минимизирует лаг-спайки от пауз GC при типичных для Minecraft паттернах аллокации (множество короткоживущих объектов).
- **Строка запуска для Java 21+ (G1GC):**

  ```bash
  java -Xms<RAM>M -Xmx<RAM>M \
  -XX:+UseG1GC \
  -XX:+ParallelRefProcEnabled \
  -XX:MaxGCPauseMillis=200 \
  -XX:+UnlockExperimentalVMOptions \
  -XX:+DisableExplicitGC \
  -XX:+AlwaysPreTouch \
  -XX:G1NewSizePercent=30 \
  -XX:G1MaxNewSizePercent=40 \
  -XX:G1HeapRegionSize=8M \
  -XX:G1ReservePercent=20 \
  -XX:G1HeapWastePercent=5 \
  -XX:G1MixedGCCountTarget=4 \
  -XX:InitiatingHeapOccupancyPercent=15 \
  -XX:G1MixedGCLiveThresholdPercent=90 \
  -XX:G1RSetUpdatingPauseTimePercent=5 \
  -XX:SurvivorRatio=32 \
  -XX:+PerfDisableSharedMem \
  -XX:MaxTenuringThreshold=1 \
  -Dusing.aikars.flags=https://mcflags.emc.gs \
  -Daikars.new.flags=true \
  -jar your-server-jar-file.jar nogui
  ```

  - Замените `<RAM>` на объём выделяемой памяти в мегабайтах (например, `10240` для 10 ГБ).
  - **Важно:** Всегда задавайте одинаковые значения для `-Xms` и `-Xmx`.
  - `-XX:+AlwaysPreTouch`: Предварительно аллоцирует страницы памяти в ОС при старте процесса.
  - Для проверки состояния кучи используйте команды `/spark health` и `/spark gcmonitor` прямо в игре.

### Высокий онлайн: Сборщики мусора с ультранизкой задержкой (150+ игроков)

На серверах со 150–300+ игроками ключевой проблемой становится **скорость аллокации объектов** (allocation rate). Minecraft непрерывно создаёт миллионы временных объектов (движение игроков, ИИ сущностей, обновления блоков, сетевые пакеты). Для таких условий разработаны генерационные сборщики с ультранизкими паузами.

- **Generational ZGC (GZGC):**
  - **Преимущества:** Сочетает субмиллисекундные паузы ZGC с разделением кучи на поколения (молодое и старшее). Часто собирает молодые объекты параллельно с работой сервера без остановки основного потока.
  - **Применение:** Мощные серверы с многоядерными процессорами и запасом оперативной памяти (16+ ГБ).
  - **Флаги для Java 21:**

    ```bash
    java -Xms<RAM>M -Xmx<RAM>M \
    -XX:+UnlockExperimentalVMOptions \
    -XX:+UseZGC \
    -XX:+ZGenerational \
    -XX:+AlwaysPreTouch \
    -XX:+DisableExplicitGC \
    -XX:+PerfDisableSharedMem \
    -XX:+UseDynamicNumberOfGCThreads \
    -jar your-server-jar-file.jar nogui
    ```

- **Generational Shenandoah:**
  - **Преимущества:** Альтернативный низколатентный сборщик, выполняющий большинство этапов параллельно.
  - **Флаги для Java 24 (экспериментальный генерационный режим):**

    ```bash
    java -Xms<RAM>M -Xmx<RAM>M \
    -XX:+UnlockExperimentalVMOptions \
    -XX:+UseShenandoahGC \
    -XX:ShenandoahGCMode=generational \
    -XX:+AlwaysPreTouch \
    -XX:+DisableExplicitGC \
    -XX:+UseNUMA \
    -XX:+AlwaysActAsServerClassMachine \
    -XX:+ParallelRefProcEnabled \
    -XX:+PerfDisableSharedMem \
    -XX:+UseDynamicNumberOfGCThreads \
    -jar your-server-jar-file.jar nogui
    ```

### Сравнение G1GC и поколенческих ZGC/Shenandoah

| Параметр | G1GC (с флагами Aikar'а) | Generational ZGC / Shenandoah |
| :--- | :--- | :--- |
| **Главная цель** | Баланс пропускной способности и пауз | Минимизация задержек (ультранизкие паузы) |
| **Типичная пауза** | Низкая, но растёт под нагрузкой (&lt;200 мс) | Экстремально низкая (&lt;1–5 мс) |
| **Нагрузка на CPU** | Умеренная, кратковременные пики во время пауз | Выше постоянная фоновая нагрузка на ядра CPU |
| **Оверхед по RAM** | Минимальный | Требует больше свободной памяти |
| **Рекомендация** | Серверы до 100 игроков | Большие серверы (150–300+ игроков) |

## Тонкая настройка рантайма и компилятора JVM

- **`-XX:+UseStringDeduplication`:** Включает дедупликацию одинаковых строк в G1GC. Экономит RAM при большом количестве текстовых данных (сообщения чата, таблички, NBT предметов).
- **`-XX:+UseNUMA`:** Активирует поддержку NUMA на многосокетных серверах или многоядерных процессорах с несколькими кристаллами (AMD EPYC, Threadripper).
- **`-XX:+UseLargePages`:** Использование больших страниц памяти (HugePages). Снижает промахи TLB при объёмах памяти >32 ГБ (требует предварительной настройки в ОС).

## Настройки серверных ядер

Помните, что флаги JVM определяют то, *как* выполняется Java, а файлы `leaf-global.yml`, `paper-world-defaults.yml` и `purpur.yml` определяют то, *что именно* делает игра. Подробные рекомендации по конфигурации Leaf приведены в руководстве [«Оптимизация сервера Leaf»](./optimize-leaf-server).
